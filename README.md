# RoadWatch — Road Damage Detection & Mapping

Professional React + Vite dashboard for an ESP32 + MPU6050 + NEO-6M road monitoring device. The map reference is Solapur, Maharashtra. The project contains **no seeded readings, sample detections, or simulated telemetry**. It remains empty until Firebase receives real device data.

## Run locally

```bash
cp .env.example .env
# Fill the Firebase values in .env
npm install
npm run dev
```

Open the Vite URL (normally http://localhost:5173). After changing `.env`, restart the Vite server.

## Login

The existing local dashboard gate remains:

- Username: `admin`
- Password: `1234`

This is a simple client-side demonstration gate, not secure authentication. Do not deploy it publicly as-is. For production, replace it with Firebase Authentication and role-based access.

## Firebase architecture

This dashboard uses **Firebase Realtime Database**. It listens in real time to:

```text
/devices/ROADWATCH-01/telemetry
/devices/ROADWATCH-01/detections/{eventId}
```

Change `VITE_DEVICE_ID` if your device uses a different ID. The dashboard derives online status from `telemetry.lastSeen` (within 60 seconds), and uses the GPS values supplied by the ESP32. Detections are sorted newest-first. All browsers connected to the same Firebase project see the same records.

### Telemetry object

Publish an object to `/devices/ROADWATCH-01/telemetry`:

```json
{
  "ax": 0.12,
  "ay": -0.08,
  "az": 9.78,
  "gx": 0.01,
  "gy": 0.02,
  "gz": -0.01,
  "magnitude": 9.78,
  "latitude": 17.6599,
  "longitude": 75.9064,
  "gpsValid": true,
  "satellites": 7,
  "speed": 12.4,
  "lastSeen": "2026-11-17T12:00:00.000Z"
}
```

Only include `temperature` if your hardware reports it. `lastSeen` must be an ISO-8601 timestamp updated on each heartbeat. Coordinates should be null or omitted until GPS has a valid fix.

### Detection record

Create a child under `/devices/ROADWATCH-01/detections` (use a unique Firebase push ID):

```json
{
  "severity": "Medium",
  "latitude": 17.6599,
  "longitude": 75.9064,
  "gpsValid": true,
  "peak": 1.91,
  "ax": 0.74,
  "ay": 0.32,
  "az": 11.10,
  "satellites": 7,
  "timestamp": "2026-11-17T12:00:00.000Z",
  "location": "Solapur road segment"
}
```

The JSON examples above describe the expected data contract; they are **not inserted into Firebase**. A Google Maps link is generated by the dashboard from each record's latitude and longitude.

## Firebase setup

1. Create a Firebase project at https://console.firebase.google.com/.
2. Create a **Realtime Database** and select its region.
3. Register a Web App in Project settings and copy its config values into `.env` (use `.env.example` as the template).
4. Create the `/devices/ROADWATCH-01/telemetry` and `/devices/ROADWATCH-01/detections` paths by sending data from your device.
5. Configure Firebase Authentication and Realtime Database Security Rules before connecting real hardware or deploying the website.

The web config values are client identifiers, not database authorization. **Do not use public read/write rules** and do not put a Firebase database secret, service-account private key, or privileged credential in `.env` or frontend code. For a secure device connection, authenticate the ESP32 with Firebase Authentication (or send device data through a trusted backend/Cloud Function) and write rules that authorize only the intended device and dashboard users. The exact rules depend on the authentication method you choose.

## Data and pages

- Overview: device connectivity, live telemetry, detection summary, latest event and Solapur map.
- Current status: MPU6050 accelerometer/gyroscope and GPS status.
- Detection history: Firebase records with Google Maps links.
- Data exports: download actual Firebase records as JSON or PDF. Export buttons remain disabled when no records exist.
- Device location: map centered on Solapur until a valid device GPS fix arrives.

## Device connectivity notes

The website listener is implemented. The ESP32 firmware must still publish the telemetry and detection objects to the Realtime Database paths above. A device can transmit from anywhere with internet access, provided it can reach Firebase and is authorized by your database rules. Wi-Fi credentials and Firebase device-auth setup belong in the ESP32 firmware configuration, not this website's `.env` file.
